Project 10: Clean Architecture and Navigation

Clean Architecture

Clean Architecture organizes code into concentric layers. The rule is that dependencies can only point inwards. The core (Domain) knows nothing about the outer layers (Data, UI).

graph TD UI[Presentation: UI/Compose] --> D[Domain: Entities/UseCases] Data[Data: Repositories/Mappers] --> D D -- Interface --> Data

Compose Navigation

Navigation in Compose uses a NavController and a NavHost. Routes are defined as strings, and arguments can be passed via placeholders in the route template.

NavHost(navController, startDestination = "list") {
    composable("list") { MovieListScreen(...) }
    composable("detail/{id}") { entry ->
        val id = entry.arguments?.getString("id")
        MovieDetailScreen(id, ...)
    }
}

Modular Design

Use Cases

Small, reusable classes that encapsulate a single business action (e.g., GetPopularMovies).

Repository Pattern

Abstracts data sources. The UI calls the Repository interface, which could be implemented by API, DB, or Mock data.

State Hoisting

Moving state up to make components stateless and easier to test and reuse.

Learning Outcomes

  • Implemented the Domain layer as the "Single Source of Truth."
  • Leveraged Compose Navigation for multi-screen app flow.
  • Passed arguments between screens using the Navigation graph.
  • Practiced layer isolation through interfaces and dependency injection.
