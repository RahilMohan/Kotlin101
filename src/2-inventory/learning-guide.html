Project 2: Data Classes and Null Safety

Data Classes & Immutability

Kotlin's data class automatically generates equals(), hashCode(), toString(), and copy(). This promotes a "Data-First" architecture where state is immutable and predictable.

data class InventoryItem(
    val id: Int,
    val name: String,
    val quantity: Int,
    val price: Double,
    val category: String? = null
)

Using .copy() allows us to "update" an item by creating a new instance with specific changes, preserving the original reference if needed for history or comparison.

The Null Safety Engine

Kotlin makes a strict distinction between nullable and non-nullable types, preventing the dreaded NullPointerException at compile time.

graph TD Var["val category: String?"] Var --> Check{Is it Null?} Check -- Yes --> SafeCall["category?.length // returns null"] Check -- No --> Access["category.length // returns length"] Check -- Default --> Elvis["category ?: 'Default' // returns 'Default'"]

Collection Operations

Kotlin's standard library provides powerful functional operators for filtering and transforming data.

filter { ... }

Returns a list containing only elements matching the given predicate (e.g., searching by name).

find { ... }

Returns the first element matching the predicate, or null if none are found.

forEach { ... }

Iterates through each element, used here to render table rows in Mordant.
