Workout Tile

Project 13: Wear OS Tiles API and Glanceable UI Design

The Tiles API Architecture

Tiles are separate from the main app activity. They run in their own process and use a remote-view-like system called ProtoLayout to ensure high performance and low battery usage.

graph LR S[Tile Service] -- "Layout Request" --> F[Layout Factory] F -- "ProtoLayout (DSL)" --> OS[Wear OS System] OS -- "Render" --> UI[Glanceable UI]

Glanceable Design Principles

A Tile should be understandable in less than 2 seconds. This requires high contrast, large typography, and minimal interactive elements (usually just one or two primary actions).

Hierarchy

Put the most important stat (e.g., current heart rate or workout time) in the largest font size in the center.

Color Coding

Use colors to indicate state or progress (e.g., Green for goal achieved, Gold for active workout).

Direct Action

Include a clear "Start" or "Open" button to minimize the steps needed to reach the main app.

ProtoLayout & Kotlin DSL

While we use a simulator here, real Tiles are built using a declarative Java/Kotlin DSL that describes a tree of layout elements (Column, Row, Box, Text, Image).

LayoutElementBuilders.Column.Builder()
    .addContent(Text.Builder().setText("Workout").build())
    .addContent(Text.Builder().setText("00:42:15").build())
    .build()
