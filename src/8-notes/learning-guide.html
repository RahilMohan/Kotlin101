Project 8: Repository Pattern, Dependency Injection, and Persistence

The Repository Pattern

A Repository mediates between the domain and data mapping layers, acting like an in-memory collection of domain objects. It hides the details of how data is saved (DB, API, File).

graph LR UI[Compose UI] --> VM[ViewModel] VM --> Repo[NoteRepository Interface] Repo --> FileRepo[File Implementation] Repo --> DBRepo[DB Implementation] FileRepo -- "JSON" --> F[(FileSystem)]

Dependency Injection (DI)

DI is a technique where an object receives its dependencies from other objects. This makes the code decoupled, testable, and easier to swap implementations.

// Instead of creating the repo inside the UI, we inject it:
@Composable
fun NotesScreen(repository: NoteRepository) { ... }
